# Desktop Git operations

The **Git** toolbar and `app.gitOperations` palette command open a lazy desktop dialog. It uses the active local review or a lightweight repository context; **Choose repository** also works without a review and with an unborn repository. Browsing never starts language servers. App-managed PR/MR checkouts are excluded from these writes; create a user-owned clone instead.

## Authority and lifecycle

`src-tauri/src/git_operations` owns admitted windows, repository contexts, immutable previews, jobs, drafts and receipts. `diffle::git::operations` supplies reusable Git validation/execution primitives. The renderer requests a typed action, receives a native preview, and confirms its opaque ID with the exact context. It cannot supply arbitrary Git arguments or patch bytes. Previews are window/context scoped, single use, expire after five minutes, and are bounded to 32 entries / 8 MiB in aggregate. Closing a context cancels reads and forgets its previews.

Execution revalidates the canonical checkout, Git/common directories and Unix device/inode identities, HEAD/refs/config/index, relevant paths and canonical patch. Index-only writes install an alternate index under an exclusively acquired real `index.lock`. Ref changes use expected old object IDs; pushes use an explicit full destination ref and expected remote object ID. App writers coordinate through common-directory ref leases, per-worktree index leases and cross-process OS locks, while still honoring Git's own locks. These checks do not make external filesystem writers, hooks or ABA changes atomic with every action.

An accepted job belongs to a native task, independent of its IPC waiter or WebView. Window close does not cancel it; normal app quit drains it through the existing session write barrier. Cancel explicitly requests process-group termination and waits for reaping, including ordinary hook descendants. Local commands have a 120-second deadline; network commands have a 300-second deadline **per command**. Git stdin is null or a supplied patch/message, never an interactive terminal. Detached user daemons and process crashes require external inspection.

A durable pending receipt precedes execution. Success, failure and interruption re-read actual Git state. Failed/cancelled writes show **Needs inspection**, with no automatic rollback/retry. After restart, a pending receipt without a live task is also uncertain; it is never replayed. **Inspect current state** observes local state and, for network operations, the URL-bound remote ref. Observation does not prove attribution or successful completion. New/partial clone and worktree destinations remain available to inspect and copy, even after failure.

Receipts live in `git-operations-v1.json` in app data, using versioning, file leases and atomic replacement. They retain at most 128 records / 2 MiB; only resolved records are evicted at the count limit. Hitting a metadata limit preserves the original file and requires inspection rather than starting more writes. Receipts contain targets, object IDs and state fingerprints, not command output, commit messages, remote URLs or application tokens. Commit messages have a separate per-canonical-checkout CAS draft file in `git-drafts-v1/`, bounded to 64 KiB of text / 512 KiB serialized. Failed saves preserve the editor text and block dialog/app-close draft flushing. A successful commit keeps the draft until edited or explicitly reloaded.

## Supported operations

| Area            | Supported behavior                                                                                     | Current boundary                                                                                                                                                                                   |
| --------------- | ------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Repositories    | Init or clone into an exclusively created folder; explicit open afterwards                             | Never reuse/delete an existing destination; retain failed/partial output; no recursive submodule clone                                                                                             |
| Refs            | Create/switch/delete branches; create/delete lightweight tags; add/remove remotes                      | Switch requires a clean checkout; branch delete requires merged and unoccupied; CAS branch deletion retains branch configuration; annotated/signed tag creation uses external Git                  |
| Changes         | Separate index/worktree/untracked views; exact file stage/unstage; canonical text hunk stage/unstage   | Hunk selection is a server-owned ordinal. Binary/add/delete/mode/symlink/filter-managed or large patches use whole-file actions. Renames appear as deletion/addition                               |
| Commits         | Commit/amend all staged paths with saved draft and explicit preview                                    | Installed hooks/signing run. Errors may leave changes and need inspection; terminal prompts use an external client                                                                                 |
| Restore/discard | Restore one worktree file from the index; permanently discard one untracked regular file               | No recursive directory deletion; symlink traversal is refused; submodule operations use external Git                                                                                               |
| Network         | Explicit fetch, local ahead/behind, fast-forward-only pull, exact-ref normal/lease push                | One identical fetch/push URL; normal push requires ancestry, pull requires a clean checkout; no automatic tags, pruning, mirroring or submodule pushes                                             |
| Worktrees       | Create from an existing branch, lock/unlock, remove clean unused checkout, prune missing registrations | No force removal of dirty/ignored-file/submodule/locked/managed/in-use checkouts; protected registrations must be recovered externally                                                             |
| Stashes         | List 100; save tracked/include-untracked; apply selected object ID; pop/drop latest                    | Apply restores index and keeps stash; pop drops only after successful apply and latest-pointer recheck. Conflicts preserve stash for external recovery. A normalized no-op save reports no changes |

Manual Git network actions use **installed Git credentials/helpers and SSH agent**, not the application's in-memory hosting connection tokens. Supported destinations are HTTPS without embedded authentication/query/fragment, SSH URI/SCP-style aliases, local `file://`, and absolute local paths. Arbitrary transport helpers are rejected. Network previews may invoke configured credential helpers to read remote refs. Never persist tokens in Git config or receipts.

Confirmed writes can run configured hooks, filters, templates, signers and helpers. Read-only status/diff previews suppress clean/smudge/process filters, fsmonitor, hooks, external diff and textconv. Consequently filter-managed files can conservatively appear modified; clean-required operations may need an external Git client. Hunk staging is disabled for those files. Existing operation/conflict states block new everyday writes; the advanced tab offers supported recovery and text resolutions, with explicit external fallbacks for unsupported states.

## Budgets and integration

The native adapter permits two reads, two local jobs and one network job. Local commands share the engine's interactive Git process budget; the separate single network admission keeps a long transfer from occupying every interactive slot. Output is drained into fixed 8 KiB buffers and discarded; no unbounded log/progress history is retained. Reads have a ten-second deadline and 2 MiB output bound, with a 30-second whole preview deadline. Catalogs stop at 2,000 changed paths, rendered in pages of 100. Diff display is capped at 64 KiB; partial staging is capped at 50 hunks / 256 KiB. Index/selected-file hashing streams with a 64 MiB bound; stash preview dirty content has a 64 MiB aggregate bound.

Catalogs and ahead/behind are lazy and explicitly refreshed. Only active jobs cause one-second receipt polling while the dialog is mounted; completion refreshes its catalog. Review watchers retain their existing refresh ownership. History refs need **Refresh refs** after the completion notice. Shared standalone reviews gain no new write routes or desktop job state.

Worktree removal checks live reviews, lightweight contexts, saved tab associations and conservative external-tool leases. Editor/terminal launches record a canonical-folder hash in `git-external-leases-v1.json` before spawning and hold a write-framework lease through spawn. Those folder protections persist across restart (256 entries / 128 KiB), with no process tracking or automatic release. After closing external tools, remove those worktrees using external Git. Embedded PTYs protect their launch checkout only while the native worker owns its lease, including after the review closes. They do not add permanent external-tool leases; see [terminal lifetime](../terminal/README.md). Agent-owned lifetime tracking remains Phase 11.

Write paths require UTF-8 in the current desktop IPC; read-only worktree/tool paths retain their native byte support. Write primitives target macOS/Linux Unix semantics. Linux runtime/visual testing is deferred by the user's Phase 8 instruction; macOS native smoke and real-Git fixture coverage are recorded in `plan.md`. Live SSH/HTTPS authentication, real provider pushes, interactive terminal/signing prompts, and whole-app heap/RSS are not established by local-bare-remote tests or bundle measurements.

## Advanced operations

The **Advanced and recovery** tab reads actual merge/pick/revert/rebase state from disk, offers valid recovery controls, and supports explicit history operations and a bounded three-way text editor. See [advanced Git ownership and supported cases](advanced.md) for index-stage labels, interactive-rebase limits, resolution drafts, external fallbacks and related-review refresh semantics. Ordinary Phase 8 writes remain blocked during an ongoing operation; recovery and exact supported conflict resolutions use the same native preview/job authority.
