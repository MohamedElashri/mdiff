# Worktrees and external tools

The desktop toolbar and command palette open a lazy browser. It can use an active review or the lightweight History repository context, so browsing does not create a review, start a language server, or launch a terminal. Existing worktrees open as working-change tabs; an already-open matching tab in the current workspace is focused. The separate [Git operations dialog](../git-operations/README.md) owns branch checkout, worktree creation/removal, staging and other writes.

## Reads and ownership

`diffle::git::worktrees` reads `git worktree list --porcelain -z`. Paths retain their native bytes, including quotes and line breaks. Inventory has a 256-entry / 2 MiB limit. Only the selected available checkout runs porcelain-v2 status; status is refreshed explicitly, with no polling, fetching, submodule traversal, hooks or optional index updates. Ahead/behind uses existing local upstream refs and can be stale relative to the server. Untracked directories count as one entry; counts describe Git status entries, not recursively enumerated files. Shallow repositories are marked and unavailable upstream counts are shown as unknown.

The native adapter allows two concurrent worktree queries process-wide, in addition to the engine's Git process scheduler. Each Git read has a ten-second deadline, bounded output, and kill-on-drop cancellation. Status now uses the shared operation read helper to suppress configured clean/process filters as well as hooks/fsmonitor; filter-managed files may conservatively appear modified. Requests belong to an admitted window and the exact review/History context, and are cancelled on context/window close and application quit. The palette searches at most 256 cached rows and returns at most 20 results without running Git while typing.

Renderer rows contain opaque IDs scoped to their native context. Before status, opening or external launch, native code re-enumerates registered worktrees and checks the selected folder's canonical Git common directory against the owner. Cached renderer paths are never launch authority. This is read-only selection validation; Git writes additionally use the operation identity/precondition framework. Linked worktrees retain distinct checkout roots and indexes while sharing repository metadata. Saved workspace metadata supplies known tab associations; it does not infer which external tools currently have the folder open. External launches additionally record a conservative canonical-folder lease before spawning; it persists across restarts and prevents app-driven worktree removal. There is no external process tracker or automatic lease release; close those tools and remove the worktree through external Git when needed.

Bare and prunable entries are visible but unavailable for review/tools. Locked entries remain usable: a Git worktree lock protects against pruning/removal, not reading. App-managed peer checkouts must be accessed through their owning saved review; opening a downloaded checkout as a new local source would lose its retention/restore ownership. Current managed checkouts can be inspected and opened externally, and external launch marks their lease for retention. Legacy unretained temporary checkouts require refreshing their remote source first. Review IPC currently requires UTF-8 paths; native non-UTF-8 paths remain inspectable and can be passed byte-for-byte to external tools.

## Installed tools and preferences

Tools are discovered only when the external-tools picker is opened, and rediscovered immediately before launch. The existing editor catalog and Linux desktop-entry support remain in use. Terminal discovery checks known application bundles and executable paths without running probe commands. No shell command is constructed from a folder path. Launchers pass the absolute folder through argv or a macOS folder-open event and set the child working directory. Git location overrides are removed from the child environment.

Supported terminal strategies:

| Platform              | Terminals                                          | Folder mechanism                                                                                                  |
| --------------------- | -------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| macOS                 | Terminal, iTerm                                    | `open -a <installed app> -- <folder>`                                                                             |
| macOS/Linux           | Ghostty                                            | `--working-directory=<folder>`, disable inherited window directory; Linux disables GTK single-instance forwarding |
| macOS/Linux           | kitty                                              | `--directory <folder>`                                                                                            |
| macOS/Linux           | Alacritty                                          | `--working-directory <folder>`                                                                                    |
| macOS/Linux           | WezTerm                                            | `start --cwd <folder>`                                                                                            |
| Linux                 | GNOME Terminal, GNOME Console, Xfce Terminal, foot | `--working-directory <folder>`                                                                                    |
| Linux                 | Konsole                                            | `--workdir <folder>`                                                                                              |
| Linux/macOS (XQuartz) | xterm                                              | inherited native working directory                                                                                |

macOS CLI-capable apps are launched with `open -n -a <app> --args …`. Terminal discovery deliberately omits generic desktop entries and `x-terminal-emulator`: they do not identify a portable folder argument contract. Missing tools/defaults are shown, without silently choosing a different saved default. No arbitrary custom shell commands are stored.

The preferred terminal is a supported catalog ID in `external-tools.json` in the native app configuration directory. Versioning, native file leases, atomic writes, compare-and-swap revisions and preference events protect concurrent windows. Discovery and preference changes never launch a shell. A successful launch means the child or Launch Services accepted the request; downstream application errors cannot always be detected. Known nonzero immediate exits are reported. Native argv tests exercise all strategies, including executable fixtures on unusual paths. Interactive macOS coverage and Linux release gaps are recorded in `plan.md`.

Primary command contracts: [Git worktrees](https://git-scm.com/docs/git-worktree), [Git status](https://git-scm.com/docs/git-status), [kitty](https://sw.kovidgoyal.net/kitty/invocation/), [Ghostty configuration](https://ghostty.org/docs/config/reference), [WezTerm](https://wezterm.org/config/launch.html), and [iTerm2 folder handling](https://github.com/gnachman/iTerm2/blob/master/sources/AppKit/iTermApplicationDelegate.m).

Embedded shells use the same native target selection, retain the launch checkout and stay with their creating window. Their live launch-folder protection ends after native cleanup; external-tool folder leases remain persistent. See [embedded terminal ownership](../terminal/README.md).
