# Agents and review

Open **Agents and review** in the toolbar/palette. Activity detection is off initially. Expand **Activity and installed tools** to opt in, choose installed Codex/Claude Code executable paths, and save an additional review focus. The executable paths are optional; discovery checks executable files on the desktop process's PATH without invoking them. Settings use native atomic writes, a size limit and compare-and-swap revisions. **Reload agent preferences** discards an unsaved local preference edit after a conflicting save.

## Explicit review handoff

From History, select a commit and **Review commit with agent**, or open a commit/branch/PR/MR comparison first. **Prepare agent review** captures the native comparison, existing open-comment prompt export and the chosen correctness/security/performance profile. The preview displays the executable, source, intended isolated folder, immutable endpoint IDs and exact prompt before a separate launch action. Preparation does not launch an agent. Working-change and empty-tree comparisons support **Copy comment prompt**; direct launch currently requires two commit endpoints. No mutable checkout is silently treated as a pinned one.

Launch consumes a native, window-bound, single-use preview (two-minute expiry, eight pending previews). It checks the comparison and configured executable/preference revision again, creates an independent local Git repository, shallow-fetches only the immutable endpoints, and checks out the head detached. The source's branch/index/unsaved files stay untouched. The new repository has its own objects and index, without alternates back to the source. Git hooks, external global config and fsmonitor are disabled for this preparation; stdout/stderr are bounded while read and commands have a timeout. Submodules, LFS downloads, intermediate commit history and arbitrary project setup are not materialized automatically. Copying a large tree can still be costly; no large-repository throughput/RSS claim is made.

Embedded runs reuse Phase 10's per-window/global PTY budgets, bounded binary streaming, input/ACK authority, Unicode renderer and close/quit barrier. Agent arguments are separate argv items, never pasted into a shell. Codex receives read-only sandbox/on-request approval settings and a separate local process; Claude keeps its normal CLI permission/trust behavior. Neither adapter supplies bypass/trust flags or app hosting credentials. User-configured agent authentication and repository instructions remain controlled by the tool. A prompt asks for review without edits/publication; it is not a sandbox guarantee for all agents.

Command-capable installed external terminals can also receive a literal command vector: kitty, WezTerm, Alacritty, Ghostty, GNOME Terminal, Konsole and xterm. Kitty startup sessions are disabled for this handoff; WezTerm targets its local domain in a new process. Folder-only Terminal/iTerm and other strategies remain available through the existing external-terminal picker and copied prompts. A successful external launch means launcher acceptance, not proof of an agent session or ownership. Native failures are reported; external processes are never stopped by mdiff. Their folder protection is a conservative persistent external lease.

All isolated folders are retained under the app data directory's `agent-reviews-v1/<id>/checkout`, including failed partial preparations. `review.json` records source/endpoint/tool/profile provenance, never prompts, output, runtime IDs or credentials. At most 16 retained folders can be created before old ones must be inspected/removed manually. There is no automatic deletion that could discard agent edits, and no restart resumes a command. Embedded runtime metadata and checkout leases are separate from workspace persistence. Review/workspace switches do not transfer existing PTYs.

## Activity provenance and limits

The process owns one monitor shared by windows. It samples only while enabled with a selected native review context, including up to 16 registered linked worktrees and known isolated launch folders, with at most 32 watched roots. It starts no review runtime/LSP and performs no network requests for polling. Sampling uses macOS libproc or Linux `/proc`; it reads executable, UID, parent/start identity and cwd, never command lines, environments, transcripts or conversation databases. Each pass has a 2,048-process/100 ms discovery budget with a rotating cursor and bounded classification cache keyed by PID/start identity. Live hook/launch states use a five-second interval; idle/unknown detection backs off to fifteen seconds. Disabled/no-context monitoring has no sampling timer. Up to 256 metadata rows are retained briefly.

A detected process has unknown task state. Its cwd can associate it with a known checkout, not a particular historical commit. Hook reports carry a tool/session identity and optional subagent identity, with parent links. Only explicit mdiff launch provenance supplies a pinned target commit or an owned terminal action. A changed process start/cwd invalidates attribution; no PID alone is authority to control a process. Hook state expires to unknown after 60 seconds without a report; rows expire after five minutes without observation. Process access restrictions, wrappers, short-lived agents and multiplexed/background servers with a different OS cwd can leave activity undetected. This is preferable to inventing a session/commit association. The status labels say **Local hook report**, **Process detected; state is unknown**, or **Explicit mdiff launch**.

## Optional local hooks

**Generate hook bundle** writes only mdiff-owned helper/config files; it never edits user or repository agent settings. With **Accept local state hooks** saved, new launches append metadata hooks in the isolated checkout's project-local settings while preserving existing hook policies and permission keys; normal tool trust still applies. The local `.codex/hooks.json` or `.claude/settings.local.json` instrumentation is outside the pinned committed comparison. CLI hook-array overrides are not used. Existing/external sessions can merge the displayed generated configuration through their normal settings workflow. No hook trust bypass is supplied. Claude and Codex support different event sets; unsupported notification events are omitted for Codex. Helpers require Python 3 on PATH. Older CLI releases may reject current flags/hook schemas and should be updated or used manually; no version probe runs during sampling.

The helper accepts at most 64 KiB of hook input, selects only event/session/subagent/cwd/notification metadata, and sends at most 8 KiB over an owner-only Unix socket. It never follows transcript paths or forwards prompt/tool/assistant content. The listener verifies the kernel peer UID/PID, a bounded supported-agent ancestor chain, process start identity, an explicitly watched cwd, enabled preferences and configuration generation. Monotonic timestamps reject old/reordered reports; payload size and I/O deadlines bound each connection. Local reports are not provider attestations, and same-account malicious code is outside this trust boundary. The helper returns no instructions or permission decisions and exits successfully on unavailable/disabled/malformed delivery.

**Uninstall hook bundle** removes generated configs and replaces the helper with an inert success-returning file. That prevents still-running sessions with old hook references from interpreting a missing helper as a tool-blocking error. Remove any manually merged references, then the inert helper folder may be removed manually. Disabling detection/hooks takes effect in native validation immediately; it does not stop unrelated agents.

The same socket is scoped to an app identifier and user. A second independent process with that identifier cannot claim a live listener. The disconnected socket can remain until the next start; only an owned socket inode is replaced. No TCP endpoint or network token is introduced.

Primary hook/argument contracts: [Claude hooks](https://code.claude.com/docs/en/hooks), [Codex hooks](https://developers.openai.com/codex/hooks/), the installed CLIs' `--help`, [kitty command vectors](https://sw.kovidgoyal.net/kitty/invocation.html), [Ghostty initial command](https://ghostty.org/docs/config/reference#initial-command), and [WezTerm start](https://wezterm.org/cli/start.html). Profiles/helper code are authored in this repository; no third-party review skill bundle is copied. Additional tools/Orca integrations should be adapters behind the same identity/provenance contract.

## Draft findings

Paste `{"findings":[{"path":"file.ts","start":2,"end":3,"body":"Explain the issue"}]}`. Native validation accepts at most 128 KiB/100 findings, requires exact changed paths, rejects traversal/nonregular or binary blobs, limits text blobs to 1 MiB and validates head-side line ranges. It rechecks the comparison before returning a draft. The UI freezes the selected tool attribution and validated head, renders finding text as text, and offers explicit copy. Attribution is user-selected, not provider-verified. No imported finding publishes a hosting review, creates a persisted comment or mutates code automatically. Raw findings JSON is an unsent workspace-tab composer draft and survives normal save/restart; after restoring or changing the comparison, validate it again. Validated list state is ephemeral.

Use `make test-native` for process/kernel-peer metadata, hook filtering and payload bounds, isolated real-Git checkouts, draft mappings, preference CAS and literal external-terminal argv. `make test-review` covers explicit launch/preview ordering, stale review responses, unavailable tools, opt-in state and local draft handling. Shared standalone history has no agent callback/launch action unless the desktop supplies it. Exact macOS smoke evidence and remaining Linux/live-provider/memory gates are in `plan.md`.
