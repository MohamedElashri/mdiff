# Needs attention

Open **Needs attention** from the toolbar or command palette. Monitoring starts paused. Choose local workspace tabs for conflict monitoring and explicitly configure GitHub/GitLab hosts and repositories for requested reviews and CI. Save **Enable monitoring** to start. Connections remains the authority for credentials; inbox settings contain no tokens. Settings use a native revision and reject conflicting saves. Reload discards an unsaved preference edit. Saving drops selections for tabs that were closed, so stale hidden IDs cannot block disabling or reconfiguring the inbox.

The inbox shows requested reviews, failed checks, unresolved index conflicts and hook-reported agent input requests before running agents and workspace/repository summaries. **Mark read** changes the unread badge; **Dismiss** hides an item without resolving it; history can restore dismissed items. Repeated observations preserve those decisions. A request becomes unread again only after a proven resolution and recurrence. Source outages, malformed responses, truncated pages and unknown agent state are unconfirmed observations, not resolution proof. Removing or pausing a configured source keeps its metadata in history. History displays up to 200 items / 256 KiB of full records, with up to 768 compact identity/read/dismiss markers inside a 512 KiB private metadata file. Display eviction does not make a still-known active observation new again; older finished/dismissed items are pruned first. Corrupt files are preserved and block writes until repaired and mdiff is restarted. Runtime agent/terminal identities are never restored from disk.

Actions resolve native item IDs rather than accepting renderer-provided paths or commands. A conflict destination revalidates its saved tab and checkout, focuses its owning workspace window and opens actual Git recovery. Requested reviews open through the existing explicit review flow. Failed-check destinations fetch checks at the **recorded immutable head**, even after the current provider head moves. Running/waiting agents can reveal an owned terminal only in its owning window; missing sessions report an error. No inbox action publishes reviews, edits code, launches shells or grants LSP trust.

## Coordinator and budgets

One coordinator in the native process serves all windows and the tray. Opening the panel subscribes to deltas; it does not create a renderer polling loop. The toolbar initially requests only a count. The coordinator reads native workspace metadata, with no review runtime or LSP startup. Local monitoring is limited to 32 selected tabs and remote monitoring to 16 configured repositories, with at most 64 known review check targets. Duplicate roots/jobs are coalesced. Existing app admission, provider HTTP caching, request coalescing, response limits, rate backoff and exact-host token binding remain in effect.

Source events can update agent rows immediately, but cannot amplify Git/network work: a monotonic budget permits at most one local recovery read and one remote summary job per 15 seconds. Normal due times are at least two minutes for the selected tab of a visible workspace and ten minutes for other repositories, with separate current/background rotation so a busy current checkout cannot starve inactive repositories. Local Git changes expedite the current checkout within the global budget. A remote job is one repository-scoped requested-review page, or a light review-head read plus bounded CI summaries (up to three HTTP reads for GitHub; two for GitLab, excluding initial account lookup). Each complete remote summary job has a twenty-second deadline. GitLab uses the latest pipeline per ref; GitHub covers latest check runs and combined commit statuses at the review head. Merge-result builds remain available through Hosting rather than automatic inbox polling. CI targets come only from configured repositories' saved PR/MR URL tabs and known requested reviews. The coordinator never fetches logs, full conversations or commit history. Missing permissions/schema/page coverage remains explicit and cannot resolve unseen failures.

Authentication discovery is cached once per host/connection epoch, including failures. Saving Connections cancels in-flight reads and discards connection caches; explicit inbox refresh can retry after an external CLI login. No CLI authentication process runs per poll. Empty/disabled monitoring has no sampling timer, and individual disabled sources perform no reads. Source-event wakeups are separate from cancellation, so frequent agent activity cannot starve an HTTP read. Accepted preference/read/dismiss writes hold the existing session gate through persistence; quit immediately cancels background reads and rejects late observations, while cancellation of quit can resume monitoring. Normal work continues while a panel is closed, backs off for inactive windows, and stops through the accepted all-window quit path. Metrics count coordinator cycles/local reads/remote jobs/notification attempts; they do not claim that every conditional HTTP read transferred a response body.

## Notifications and closing

OS notifications, each notification source, the menu bar/tray entry and **Keep windows in the menu bar / tray when closed** are explicit preferences. Alerts use generic text and a native item identity, without repository titles, paths or credentials. The locked Tauri notification plugin's desktop body-click callback routes through the same native destination validation; expired/paused destinations fall back to the inbox. Delivery depends on OS notification settings/service availability. The in-app inbox is always available. To bound desktop notification waiter threads, attempts have a one-minute global cooldown and a maximum of 16 per app run; excess events remain unread in the inbox. No startup replay of stored notifications occurs.

The tray includes the unread count, up to five current destinations, **Needs attention** and **Quit mdiff**. Tray initialization failure is reported and cannot enable hidden close behavior. By default window close follows the existing save/terminal confirmation flow. With the explicit keep-in-tray preference and a working tray, close hides the existing window: its reviews, terminal jobs and monitoring stay alive and consume their existing budgets. Reopen from the tray/Dock restores that window. Quit always reveals hidden windows for save/terminal confirmation and uses the existing all-window exit barrier. There is no autostart or independent background daemon.

Linux tray/notification/runtime behavior is deferred to Linux per the user's instruction. The full app view remains the fallback for missing services. macOS native smoke, resource measurements, exact suite counts and other outstanding gates belong in `plan.md`. Primary platform contracts: [Tauri tray](https://v2.tauri.app/learn/system-tray/) and the locked `tauri-plugin-notification` Rust desktop implementation (2.8.1 includes desktop body-click callbacks; older website documentation describes actions as mobile-only). No project installs external review skills or copies provider material.
