# Embedded terminal

Open **Embedded terminal** in the toolbar or command palette, then explicitly **Start shell** in the selected review/History checkout. **Worktrees and tools → Start embedded terminal in this worktree** starts in that native-validated selection. Each window has at most two terminal tabs; the process has at most four live PTYs. The panel is optional and loaded on demand. **Allow new shells** disables startup, and the existing external-terminal picker remains available.

## Authority and lifetime

The creating window owns a shell. Review/workspace switches, moving a review to another window, hiding the panel and closing a review do not change its launch directory or transfer/terminate it. The displayed path is its original directory; commands can `cd` elsewhere. A terminal tab closes only after an explicit stop confirmation when live. Window close and app quit/restart save drafts and ask about live shells. Global quit stops shells only after every window acknowledges the existing native exit barrier. A cancelled quit preserves them. On macOS an AppKit `applicationShouldTerminate:` hook forwards menu/Cmd+Q/Dock termination into this barrier; the pinned Tao delegate otherwise bypasses `ExitRequested` ([upstream](https://github.com/tauri-apps/tauri/issues/9198), [AppKit contract](<https://developer.apple.com/documentation/appkit/nsapplicationdelegate/applicationshouldterminate(_:)>)). It cancels the original AppKit termination immediately, then accepted quit uses Tauri's owned exit path. A system logout/shutdown request can therefore need repeating after mdiff exits; no nested termination modal loop or automatic OS-shutdown resumption is promised. The hook refuses to overwrite an existing delegate implementation, so a future runtime change fails visibly and requires revisiting this bridge. Native teardown also handles WebView reload/destruction; commands and terminal contents are never restored or attached to a replacement document.

Native `terminal_start` accepts an owned review/History context and optional opaque worktree ID, never a path or arbitrary executable. It holds the checkout target and process/window admission permits through cleanup, revalidates Git identity under the shared common-dir/index locks, and enters the window registry before releasing startup locks. The terminal registry prevents app removal of its live launch checkout. This protects known launch locations, not arbitrary directories later visited with `cd`. Shell Git commands are user-controlled and do not participate in app preview locks; the existing Git stale checks and Git's own locks still apply.

Managed downloaded checkouts are marked editable and retained conservatively, even if the shell appears clean. Legacy unretainable temporary checkouts must be refreshed before shell startup. The launch target stays leased until native PTY/process cleanup completes, including after its review closes. App-owned PTY leases expire at cleanup; external-tool leases remain conservative persistent folder protections (Phase 8), since mdiff does not own those processes.

The shell is the inherited absolute `$SHELL` (fallback `/bin/zsh` on macOS, `/bin/bash` on Linux), invoked as an interactive login shell in the checkout. Invalid/unavailable shells fail visibly. No startup command is stored. The environment removes Git location/pathspec/config injections, askpass overrides, known hosting-token variables and Rex pane IDs. In-memory app connection credentials are never injected. A normal shell still reads the user's login files, uses their local credentials/tools and may maintain its own history; mdiff does not log/persist input or output.

## PTY and renderer

Pinned components: [`portable-pty` 0.9.0](https://docs.rs/portable-pty/0.9.0/portable_pty/) provides real controlling-TTY/session creation and resize; [`@xterm/xterm` 6.0.0](https://www.npmjs.com/package/@xterm/xterm/v/6.0.0) and [`@xterm/addon-fit` 0.11.0](https://www.npmjs.com/package/@xterm/addon-fit/v/0.11.0) provide the VT parser, Unicode decoding, browser renderer and measured cell sizing. These maintained cross-platform components avoid implementing a VT parser/PTY abstraction locally. Actual native adapters are Unix-only, matching mdiff's macOS/Linux targets. Notices are generated with `make notices TARGET=<triple>`; no shell plugin or broad filesystem permission is added. Only the existing native dialog plugin gains confirmation permission.

Each PTY has one nonblocking worker and a 16-command queue. Input admission is atomic, at most 64 KiB outstanding in each frontend/native queue; busy/oversized input is rejected visibly and never retried automatically. Resize is coalesced for 80 ms and clamped to 2–300 columns, 1–120 rows. Polling wakes immediately for output and checks input/control commands within 20 ms.

Output uses a Tauri binary `Channel<Response>`, outside review HTTP/JSON and React state. Each frame is a 16-byte little-endian header (`u64 sequence`, `u32 kind`, four reserved zero bytes) plus payload. Data kind 0 contains at most 8 KiB. Four unacknowledged data frames (32 KiB) are allowed, including before the start reply; reading then stalls at the PTY. xterm receives raw bytes so UTF-8 splits are preserved. Its write/parse callback produces cumulative acknowledgements, coalesced for 16 ms. Native ACKs reject future/unissued sequences. Exit kind 1 has sequence 0 and a small `{code,message}` JSON payload. The frontend rejects bad sizes/kinds/sequences, stops a broken stream, and does not replay input. xterm retains 1,000 scrollback lines plus the bounded screen; output fragments do not notify React subscribers.

The renderer uses the app palette/code font, xterm minimum foreground contrast of 4.5:1 (including ANSI colors on light backgrounds) and a persisted 10–24 px size. Clipboard copying requires an explicit selection action. OSC 52 clipboard and OSC 9 notification escapes are consumed; OSC 8 links have inert handlers. No shell integration, link opener, title-driven app action, clipboard-read, image or privileged escape addon is installed. Terminal focus is inside the existing keyboard isolation boundary.

On stop, native code signals all processes in the PTY's Unix session, allows 250 ms for TERM, escalates to KILL, reaps its owned shell, closes all PTY handles, and releases checkout/admission leases. The session leader is left unreaped during enumeration/signalling to prevent reuse of its session ID. An owned-child guard also cleans up failed worker-thread creation/unwinding. Natural exit preserves output credit and drains the remaining PTY tail; explicit stop may discard the unread tail. Processes deliberately daemonizing into a different session are outside this ownership boundary, as with ordinary terminals. App crashes/force-kill cannot offer normal close confirmation/cleanup guarantees.

## Validation

Use `make test-native` for real PTY Unicode/cwd/input/resize, finite-credit floods/final tails, TERM-ignoring background jobs, dropped controllers, admission/owner isolation, checkout lease lifetime and revisioned preferences. `make test-review` covers parser acknowledgements, no output React notifications, startup/exit races, invalid frames, paste rejection, resize, explicit startup/tab-close confirmation, worktree IDs and the quit barrier. Shared standalone commands have no embedded-terminal handler.

macOS interactive native evidence and deferred Linux acceptance are recorded in `plan.md`. Linux process enumeration, shell/job control, WebKit rendering, clipboard, resize and shutdown must be validated/fixed on Linux after the feasible macOS work, as requested. No full multi-WebView RSS/startup claim is inferred from bounded queues or bundle sizes.
